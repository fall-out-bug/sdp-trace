# Вопросы заказчика

Эта карта отвечает на обязательные pilot-вопросы для handoff и не превращает
local evidence в external production trust. Каждый ответ называет artifact или
command, который заказчик должен проверить, и residual state, если evidence
недоступно.

| # | Вопрос заказчика | Ответ | Что смотреть | Residual state |
| --- | --- | --- | --- | --- |
| 1 | Чем это лучше, чем CI logs, git diff и review comments по отдельности? | CI logs, diffs и comments разорваны между собой. `sdp-trace` добавляет portable contract, который связывает task, command, provenance, evidence, retained artifacts, missing telemetry, assessment profile, witness state и release manifest checks. | `.sdp-trace-report/summary.json`, `.sdp-trace-report/evidence-table.json`, `.sdp-trace-runs/<run-id>/`, `go run ./cmd/sdp-trace explain <run-dir>` | Сам по себе `sdp-trace` не решает readiness или quality; policy остается вне repo. |
| 2 | Можно ли подключить sidecar-first без замены существующего harness? | Да. Начните с `wrap` вокруг существующей command, затем добавляйте adapter events или managed profile inputs только там, где harness может их emit. | `go run ./cmd/sdp-trace wrap --name <workflow-name> --output-dir .sdp-trace-runs/<run-id> -- <existing command...>`, `go run ./cmd/sdp-trace run --task <task-ref> -- <command...>` | Harness internals не видны, если они не wrapped и не emitted через adapter. |
| 3 | Что происходит, если agent или developer обходит wrapper или adapter? | Bypass не восстанавливается из ничего. Он проявляется как missing required run evidence, missing adapter events, missing managed witness binding или lower trust scope. | `.sdp-trace-report/missing-telemetry.json`, `go run ./cmd/sdp-trace query --query missing-evidence <run-dir>`, `go run ./cmd/sdp-trace assess --profile adapter-capture --out assessment.json --run <run-dir>` | Bypass evidence остается `missing_telemetry`, `not_assessed`, `cannot_verify` или `fail`; это нельзя превращать в pass. |
| 4 | Как отличить реальное process movement от missing telemetry? | Real movement имеет observed runs, evidence rows, provenance, metric/posture rows и profile states. Missing telemetry называется отдельно и не попадает в pass claims. | `.sdp-trace-report/evidence-table.json`, `.sdp-trace-report/missing-telemetry.json`, `go run ./cmd/sdp-trace export cross-repo-posture --profile cross-repo-evidence-posture-v1 --selection <file> --out <file>` | Cross-repo posture export - evidence для downstream analysis, а не native degradation verdict. |
| 5 | Какие states являются `not_assessed` или `cannot_verify`, и что CTO должен с ними делать? | `not_assessed` значит, что выбранный run не оценивал этот state. `cannot_verify` значит, что verifier пытался проверить state, но не хватило evidence, environment или consistency. CTO должен удержать claim, запросить evidence, сузить scope или принять это как named non-goal. | Command output, assessment result JSON, `.sdp-trace-report/gate-result.json`, witness output, release-proof output | Ни один из этих states не является pass. Для trust claims `cannot_verify` fail-closed. |
| 6 | Какое proof есть для local source-bound release, и какой external production trust отсутствует? | `release-proof` может проверить manifest subject digests against named source commit и local proof artifacts. External production trust все еще требует accepted external identity, protected source, workflow identity, transparency или customer audit evidence, approval, freshness и production release verification. | `go run ./cmd/sdp-trace release-proof --manifest examples/contract-foundation/contract-manifest.example.json --out release-proof.json`, `docs/contract-release-signing.md` | `source_bound_local_release` не равен `external_production_trust`; `trusted_contract_release` и `production_release_verified` остаются false/absent, пока внешний profile не прошел. |
| 7 | Какой artifact отвечает на каждый вопрос в `.sdp-trace-report/`, `.sdp-trace-runs/`, examples или SpecKit docs? | Report artifacts отвечают на вопросы про run/evidence/gaps, run directories - на local trace reconstruction, examples показывают valid fixture shapes, SpecKit docs фиксируют scope и non-goals. | `.sdp-trace-report/summary.json`, `evidence-table.json`, `missing-telemetry.json`, `gate-result.json`, witness artifacts, `.sdp-trace-runs/<run-id>/`, `examples/`, `specs/001-sdp-trace-time-series-evidence-substrate/` | Checked-in examples и specs не authority, пока не validated текущими commands. |
| 8 | Какие данные intentionally не captured или не committed for privacy? | Raw customer source, credentials, provider tokens, private prompts, raw model responses, authenticated URLs, OIDC request tokens и raw logs не должны попадать в commit. Используйте digests, sanitized excerpts, encrypted external refs, redaction state и access notes. | `docs/evidence-policy.md`, `docs/harness-integration.md`, `docs/team-lead-playbook.ru.md`, forensic retention assessment output | Если raw evidence недоступно по policy, forensic reconstruction может быть limited или `cannot_verify`. |
| 9 | Какие CI и enterprise witness profiles shipped now, а какие unsupported или documentation-only? | Shipped `witness --kind` values: `github-actions`, `gitlab-ci`, `buildkite`, `customer-pki`. Air-gapped guidance - это customer-policy/private-equivalent guidance, а не отдельный witness kind. | `go run ./cmd/sdp-trace --help`, `go run ./cmd/sdp-trace witness --kind <github-actions|gitlab-ci|buildkite|customer-pki> --out <file> [inputs] <runs-root-or-run-dir>`, `docs/agent-entrypoint.md` | CI/customer witness сам по себе не external production trust. Unsupported witness kinds - usage errors или `not_assessed` follow-ups. |

## Caveats для handoff

- `gate` выдает verifier facts; он не принимает merge, release, readiness,
  degradation, override или risk decisions.
- `witness` связывает доступное CI/customer evidence; он не дает production
  trust без selected passing external trust profile.
- `release-proof` устанавливает только local source-bound release proof, если
  external production trust evidence отсутствует или не verified.
