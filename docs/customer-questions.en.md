# Customer Questions

This map answers the mandatory pilot handoff questions without treating local
evidence as external production trust. Every answer names the artifact or command
that a customer should inspect and the residual state when evidence is missing.

| # | Customer question | Answer | Inspect | Residual state |
| --- | --- | --- | --- | --- |
| 1 | How is this better than CI logs, git diff, and review comments alone? | CI logs, diffs, and comments are disconnected evidence. `sdp-trace` adds a portable contract that links task, command, provenance, evidence, retained artifacts, missing telemetry, assessment profile, witness state, and release manifest checks. | `.sdp-trace-report/summary.json`, `.sdp-trace-report/evidence-table.json`, `.sdp-trace-runs/<run-id>/`, `go run ./cmd/sdp-trace explain <run-dir>` | It does not decide readiness or quality by itself; policy remains outside `sdp-trace`. |
| 2 | Can it attach sidecar-first without replacing the existing harness? | Yes. Start with `wrap` around the existing command, then add adapter events or managed profile inputs only where the harness can emit them. | `go run ./cmd/sdp-trace wrap --name <workflow-name> --output-dir .sdp-trace-runs/<run-id> -- <existing command...>`, `go run ./cmd/sdp-trace run --task <task-ref> -- <command...>` | Harness internals are not visible unless wrapped or emitted through an adapter. |
| 3 | What happens when an agent or developer bypasses the wrapper or adapter? | The bypass is not reconstructed from nothing. It appears as missing required run evidence, missing adapter events, missing managed witness binding, or a lower trust scope. | `.sdp-trace-report/missing-telemetry.json`, `go run ./cmd/sdp-trace query --query missing-evidence <run-dir>`, `go run ./cmd/sdp-trace assess --profile adapter-capture --out assessment.json --run <run-dir>` | Bypass evidence is `missing_telemetry`, `not_assessed`, `cannot_verify`, or `fail`; it must not be converted to pass. |
| 4 | How does it distinguish real process movement from missing telemetry? | Real movement has observed runs, evidence rows, provenance, metric/posture rows, and profile states. Missing telemetry is named separately and kept out of pass claims. | `.sdp-trace-report/evidence-table.json`, `.sdp-trace-report/missing-telemetry.json`, `go run ./cmd/sdp-trace export cross-repo-posture --profile cross-repo-evidence-posture-v1 --selection <file> --out <file>` | Cross-repo posture export is evidence for downstream analysis, not a native degradation verdict. |
| 5 | Which states are `not_assessed` or `cannot_verify`, and what should a CTO do with them? | `not_assessed` means the selected run did not assess the state. `cannot_verify` means the verifier attempted the check but lacked required evidence, environment, or consistency. A CTO should hold back the related claim, require evidence, narrow scope, or accept it as a named non-goal. | Command output, assessment result JSON, `.sdp-trace-report/gate-result.json`, witness output, release-proof output | Neither state is a pass. For trust claims, treat `cannot_verify` as fail-closed. |
| 6 | What proof exists for a local source-bound release, and what external production trust is still absent? | `release-proof` can verify manifest subject digests against a named source commit and local proof artifacts. External production trust still requires accepted external identity, protected source, workflow identity, transparency or customer audit evidence, approval, freshness, and production release verification. | `go run ./cmd/sdp-trace release-proof --manifest examples/contract-foundation/contract-manifest.example.json --out release-proof.json`, `docs/contract-release-signing.md` | `source_bound_local_release` is not `external_production_trust`; `trusted_contract_release` and `production_release_verified` remain false/absent unless the external profile passes. |
| 7 | Which artifact answers each question in `.sdp-trace-report/`, `.sdp-trace-runs/`, examples, or SpecKit docs? | Report artifacts answer run/evidence/gap questions, run directories answer local trace reconstruction, examples show valid fixture shapes, and SpecKit docs answer intended scope and non-goals. | `.sdp-trace-report/summary.json`, `evidence-table.json`, `missing-telemetry.json`, `gate-result.json`, witness artifacts, `.sdp-trace-runs/<run-id>/`, `examples/`, `specs/001-sdp-trace-time-series-evidence-substrate/` | Checked-in examples and specs are not authority unless validated by current commands. |
| 8 | What data is intentionally not captured or not committed for privacy? | Raw customer source, credentials, provider tokens, private prompts, raw model responses, authenticated URLs, OIDC request tokens, and raw logs should not be committed. Use digests, sanitized excerpts, encrypted external refs, redaction state, and access notes. | `docs/evidence-policy.md`, `docs/harness-integration.md`, `docs/team-lead-playbook.en.md`, forensic retention assessment output | If raw evidence is unavailable by policy, forensic reconstruction may be limited or `cannot_verify`. |
| 9 | Which CI and enterprise witness profiles are shipped now, and which remain unsupported or documentation-only? | Shipped `witness --kind` values are `github-actions`, `gitlab-ci`, `buildkite`, and `customer-pki`. Air-gapped guidance is customer-policy/private-equivalent guidance, not a separate witness kind. | `go run ./cmd/sdp-trace --help`, `go run ./cmd/sdp-trace witness --kind <github-actions|gitlab-ci|buildkite|customer-pki> --out <file> [inputs] <runs-root-or-run-dir>`, `docs/agent-entrypoint.md` | CI/customer witness is not external production trust by itself. Unsupported witness kinds are usage errors or `not_assessed` follow-ups. |

## Caveats For Handoff

- `gate` emits verifier facts; it does not make merge, release, readiness,
  degradation, override, or risk decisions.
- `witness` binds available CI/customer evidence; it does not provide production
  trust without a selected passing external trust profile.
- `release-proof` establishes only local source-bound release proof unless
  external production trust evidence is present and verified.
