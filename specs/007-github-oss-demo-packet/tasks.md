## Demo Feature Route Rule

For CTO-visible feature work, Codex may coordinate, review, inspect, run
verification, and fix P0 `sdp-trace` product blockers. Codex must not implement
or repair demo feature behavior directly. Required feature implementation route:
OpenCode + GSD + `minimax-coding-plan/MiniMax-M2.5` under passive `sdp-trace`
observation.

If a feature fails, Codex redirects OpenCode/GSD with a new task or prompt. If
the recorder cannot prove the route, P0 `sdp-trace` issues are fixed before
claiming the feature packet; P1 and lower issues are recorded and can follow
after feature delivery unless they block the demo proof.

At least one happy-path CTO-visible feature packet must have
`PC-AGENT-ROUTE: pass` or `partial` backed by recorder-observed
OpenCode/GSD/MiniMax evidence before demo success can be claimed.

Checked-in recorder artifacts are not authority by themselves. Each feature
packet must either use live-validated or CI-retained recorder artifacts with
resolver refs and digests, or explicitly mark the affected proof area
`cannot_verify`/`partial` with a residual gap. Prompt/setup metadata alone may
support route proof only as `partial`; `PC-AGENT-ROUTE: pass` requires stronger
machine evidence of recorder integrity and passivity.
