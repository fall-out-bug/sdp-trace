# Wrap Output / Schema Drift Example

Status: historical drift evidence; resolved for live `wrap` by
`schema/run-manifest.schema.json`
Spec: [017](../../../specs/017-oss-replacement-compatibility-and-benchmarks/)

This directory preserves structural evidence that an older `run.json` artifact
produced by `sdp-trace wrap /bin/true` did not conform to
`schema/flight-recorder-run.schema.json`. Live `wrap` output is now validated
against `schema/run-manifest.schema.json`, which represents the current
recorder manifest contract.

For live verification of the current checkout, run:
`go run ./tools/osscompat -probe jsonschema-wrap-manifest`.
The former probe name `jsonschema-wrap-drift` remains accepted as a legacy
alias for existing local scripts.

## Frozen Snapshot

The file `run.json` in this directory is a **frozen historical snapshot** of the
recorder manifest generated by `sdp-trace wrap /bin/true` during spec 017
development. It is not regenerated on every build; it exists as structural
evidence that the generated manifest once differed from
`schema/flight-recorder-run.schema.json`.

The companion file `wrap-output.txt` captures the CLI stdout (`run_dir: ...`)
for context; it is not the subject of schema validation.

> **Note:** The run ID and paths are nondeterministic across invocations.
> This fixture is frozen as structural evidence; the exact values do not affect
> the drift claim, which depends on schema-level mismatches. If `sdp-trace wrap`
> output changes in the future, this snapshot does not automatically update.

## Schema Expectation

`schema/flight-recorder-run.schema.json` requires a JSON object with these
required fields:

- `schema_version` (const `"1.0.0"`)
- `run_id`
- `profile`
- `trust_scope`
- `artifact_role`
- `created_at` (ISO-8601 timestamp)
- `source_summary`
- `task_summary`
- `model_summary`
- `harness_summary`
- `evidence_retention_summary`
- `verifier_states`

## Blocker Status

The live blocker is resolved by defining `schema/run-manifest.schema.json` as
